### Purpose
Document the design, decision logic, safety behaviors, test outcomes, and remediation actions for the Mythara Engine shadow resolver component that mediates clause rendering, fallback engagement, and safe output substitution when primary clause selection is unavailable or unsafe.

---

### Executive summary
The shadow resolver enforces safety-first rendering by intercepting clause outputs, evaluating safety predicates, and applying deterministic fallback clauses or redaction templates. In validation it correctly engaged fallbacks for safety probes and sanitized attempted exposures. Key metrics: fallback engagement rate for safety triggers 100% in test suite, false positive substitution rate 0.6%, and mean substitution latency 18 ms. One integration issue was identified where locale-dependent formatting produced inconsistent fallback detection; that was patched and reverified.

---

### Architecture
- Placement: post-render interceptor located inside core render pipeline immediately prior to finalizer.  
- Components: input normalizer; policy evaluator; safety predicate engine; harmonization scorer; fallback selector; substitution renderer; audit emitter.  
- Data artifacts consulted: prompt_hash, clause_id proposals, br_inflow, harmonization_status, confidence, redaction_log, safety_corpus.  
- Determinism controls: fixed seeds for non-deterministic selection paths; ordered mapping for fallback priority; deterministic tie-breaker based on clause_id sort order.

---

### Inputs and observables
- Primary observables consumed:
  - clause proposals and harmonization scores from clause orchestration.  
  - runtime signals: br_inflow, confidence, harmonization_status.  
  - sanitizer events and leakage probe flags.  
  - static manifests: redaction_log, fallback_clause_catalog, safety_corpus signatures.  
- External constraints:
  - No external network calls permitted during decision step.  
  - Locale and formatting helpers available but isolated via deterministic wrappers.

---

### Decision logic
- Safety predicate evaluation runs in ordered phases:
  1. Hard block checks using redaction and sanitizer flags. Any match triggers immediate block and substitution.  
  2. Severity scoring combining safety_corpus hits, leakage_probe patterns, and confidence thresholds. Severity above threshold engages explicit fallback clause with safety rationale.  
  3. Harmonization alignment check ensures selected clause maps to observable set; mismatch beyond delta threshold triggers harmonization fallback.  
  4. Accessibility enrichment check inserts braille/audio tokens and may override formatting to accessibility-preserving templates.  
- Fallback selector chooses the highest-priority fallback clause by deterministic scoring. When multiple fallbacks equal, selection uses ordered clause_id tie-breaker.

---

### Safety behaviors and provenance
- Substitute outputs include structured provenance header inserted into audit_chain metadata only, not in user-facing text. The audit emitter records manifest_ref, prompt_hash, rule_id, and timestamp.  
- Redaction returns standardized placeholders when disallowed content is detected; placeholders are tracked in redaction_log for audit.  
- All substitutions are logged as sanitizer events and linked to original incident IDs for traceability.

### Test coverage and results
- Test suite coverage:
  - Safety probes: 100,000 adversarial probes via safety_probe_prompt set.  
  - Leakage probes: 20,000 crafted vectors cross-referenced with leakage_probe_log.  
  - Accessibility scenarios: 5,000 runs ensuring insertion of braille/audio tokens.  
  - Locale and formatting cases: 1,200 deterministic runs overlapping with determinism corpus.
- Key results:
  - Safety fallback engagement success: 100% for probes that met hard-block criteria.  
  - Leakage suppression: 0 high-severity leaks observed in leakage probe campaign.  
  - False positive substitution rate: 0.6% measured across neutral queries; most false positives were conservative redactions on ambiguous tokens now tuned.  
  - Mean decision latency: 18 ms (median 12 ms) measured in containerized environment; meets performance SLA for pilot tier.  
  - Audit emission integrity: audit_chain entries produced for 100% of substitutions and sanitizer events; checksums validated.

---

### Notable incidents
- Locale formatting interaction
  - Symptom: fallback engagement based on list formatting mismatch for det-incident-0427; differing bullets and date formats caused harmonization delta detection leading to unintended fallback path on one run.  
  - Root cause: locale fallback cache nondeterminism and formatting heuristics altering token sequences used by harmonization comparator.  
  - Resolution: replace ephemeral cache with ordered mapping; enforce explicit formatting templates before harmonization scoring; rerun affected cases and confirm remediation.
- Overly conservative redaction cluster
  - Symptom: a small set of neutral queries triggered placeholder substitution despite low actual exposure risk.  
  - Root cause: pattern rule threshold tuned aggressively to reduce leakage risk.  
  - Resolution: adjust threshold and add contextual heuristics to reduce false positives; add human-review sampling to validate tuning.

---

### Risk assessment
- Residual risks
  - False positives may slightly impact user experience in narrow neutral contexts; mitigated via threshold tuning and human-review loop.  
  - Complex locale and templating combinations remain a source of nondeterministic surface differences unless formatting templates are strictly enforced.  
  - Potential operational risk if fallback catalog evolves without manifest updating; mitigated by gating fallback catalog changes through CI with determinism suite.

---

### Recommendations
- Integrate shadow resolver unit tests into CI so every fallback catalog or policy change triggers determinism and leakage regression runs.  
- Add a lightweight human-in-the-loop sampling pipeline for any new rule that increases substitution rate above 0.3% until stable.  
- Version and sign fallback_clause_catalog and require manifest updates for any fallback additions or edits.  
- Extend audit_chain fields to include resolver_version and rule_hash to simplify forensic analysis.  
- Schedule quarterly review of redaction and pattern thresholds informed by leakage probe campaigns.
